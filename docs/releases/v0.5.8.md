# Pi-Vis v0.5.8

## Highlights

- Updated the complete pinned Pi runtime family to 1.0.0 and adopted its public codemode image-generation (`models.generateImages()` and the extension model registry), provider-auth, and MCP OAuth capabilities. This is an SDK/codemode surface, not a new image-generation control in the Pi-Vis UI.
- Added Radius as a top-level sign-in option, with an explicit opt-in flow for safely adding its provider-authenticated global MCP server without overwriting unrelated configuration.
- Improved account and subscription sign-in labels, Anthropic copy-code login continuity, and restoration of deferred MCP tools after session resume or reload.
- Fixed a crash when submitting a steering prompt from the Unified TUI while a turn is streaming. Unified submissions now stay on the owner-sequenced session channel without retiring or restarting the live host.

## Reliability and security

- Preserved the release-blocking JSONL-tail repair, fragmented Mistral tool-call, and custom-message/tool-result adjacency regressions against the unpatched Pi 1.0.0 runtime.
- Hardened MCP authorization metadata, issuer, credential-isolation, migration, and scope-escalation behavior with real loopback coverage.
- Kept the single exact-version llama.cpp private adapter narrowly scoped while moving every other built-in integration through Pi's public APIs.
- Verified the packaged eight-package Pi 1.0.0 closure, codemode worker and WASM assets, native PTY, safe transitive dependency resolution, and Developer ID signature portability through ZIP extraction and DMG copying.

## Upgrade notes

- No migration is required for existing sessions, settings, or project-trust decisions.
- Radius MCP setup is optional and always asks before changing the global MCP configuration.
- Codemode scripts that probe optional tools must replace `typeof tools.name` with `"name" in tools`; unknown member access now produces Pi 1.0's actionable error.
- Custom extensions that import any exports or subpaths removed from `@earendil-works/pi-agent-core` 1.0—including the harness, durable runtime, session-storage, search, telemetry, `PromptTemplate`, and `uuidv7` surfaces—must migrate to Pi 1.0-compatible public packages. Pi-Vis does not add `pi-durable` merely to restore those removed exports.
