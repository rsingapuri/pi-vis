# State and sessions

## Authority and renderer projection

The SDK-host `AgentSession` is the sole live-state authority. `state-authority.mjs` takes direct reads from public SDK getters, resolves getter/event disagreement inside the child, and serializes each semantic commit as an authority frame: ordered records plus a complete terminal snapshot with owner, epoch, and sequences. It does not derive semantic state from `agent_*`, retry, or transcript events.

`SessionRegistry` accepts only active-owner publications and routes frames without reducing or splitting them. Its identity/epoch checks, availability lease, and direct runtime snapshots are transport/compatibility diagnostics, not an alternate semantic projection. A frame's typed child-authored runtime-resume checkpoint is the narrow exception to ordinary opaque routing: main may retain it as an owner-local continuation token and return it unchanged only when replacing that same session record's host. Main never derives this token from a compatibility snapshot or uses it to choose a model. The successor child applies it only to its initial runtime-factory invocation and only where the public `SessionManager` branch has no persisted model/thinking identity; Pi's reuse of that factory for `/new`, `/resume`, `/fork`, and import never carries the checkpoint into a different session. Explicit branch metadata remains authoritative. The host's periodic publication emits a semantic frame plus a direct control snapshot from the same child read: the frame advances canonical state, while only the control snapshot renews the independent availability lease. On a lease failure or discontinuity it fences the relevant authority plane and requests a baseline; UI selectors treat unavailable or synchronizing state as unknown, never idle or a completed turn. Sidebar completion requires a following semantic projection at its named owner/cursor. Owner-bound read-only `session.query` returns typed `ok`, `superseded`, `transitioning`, or `unavailable` data rather than throwing lifecycle races across IPC. `session.authorityAttach` likewise returns only typed `ready`, `transitioning`, or `unavailable` data; callers install an authority baseline only for `ready`.


Lifecycle admission is child-owned. Before reload, worktree respawn, or narrow activation-visit release, main requests the host's serialized opaque lifecycle permit. The child samples direct SDK getters and custody, intents, queues, editor, and extension UI in one authority transaction and returns only an allowed/reason verdict. Main rechecks only process identity, transport availability, and local lifecycle fences after awaiting it; reload repeats the child check at its transition boundary. Retained intents are retired by explicit child dispositions/outcomes, never because main observes an idle snapshot.

The Zustand session store is a projection of this authority plus renderer-only presentation state (transcript blocks, drafts, overlays, notifications, and panel buffers). Transcript events render history and activity; they do not define runtime liveness. Installing a complete child-owned navigation branch advances renderer history ownership and cancels any persisted hydration captured against the prior leaf; stale pre-ack attach escrow is re-acknowledged from a bounded renderer tombstone without reconverting the branch. The final `agent_settled` presentation event promotes a background turn's flashing sidebar indicator to a retained solid done/error notification; it never changes streaming/idle authority, and `agent_start` clears the prior notification.

## Deployed authority-frame projection

[ADR 0003](../decisions/0003-authority-frames-and-plane-synchronization.md) defines the deployed projection. It deliberately does **not** promise that renderer state equals Pi state at the same instant. A `following` plane is exact only as of its named authority cursor—`(hostInstanceId, sessionEpoch, transportSequence, snapshotSequence)`—and contains all complete frames received through that cursor. A child mutation after the cursor may be unknown to the renderer until publication arrives.

The authority reducer owns one `PlaneSync` state per semantic control, transcript, extension-UI, and panel plane: `following(cursor)`, `synchronizing(lastCursor, reason)`, or `unavailable(lastCursor, reason)`. A gap in a known source-plane cursor fences only that plane; it does not turn unrelated following planes into guesses. A gap in main's single global publication sequence has unknown source-plane attribution, so it fences every plane until a serialized baseline is installed. While synchronizing, retained values are diagnostics visibly marked stale and controls requiring that plane are fenced. A fenced extension-UI plane retains its last status/widget presentation until its own following baseline replaces it; semantic publications cannot clear it. By [ADR 0005](../decisions/0005-retain-presentation-labels-across-authority-fences.md), a fenced semantic plane likewise retains last-known session/model/thinking labels as stale presentation while clearing dispatch/control fields. No plane returns to following from silence or unrelated events.

Each child authority commit emits an atomic semantic frame: ordered records plus a complete terminal semantic snapshot at one owner/cursor. The renderer reduces the whole frame in one store commit and never combines records or snapshots from different cursors. High-volume transcript deltas, live Shell Turn VT bytes, and terminal panel bytes have presentation-plane cursors and cannot mutate semantic control state. Full navigation branches are likewise presentation custody rather than repeated semantic snapshot state: the live terminal record is the fast path, attach is the recovery path, and the child retains the branch until an exact owner/intent acknowledgement after transcript installation. Owner replacement atomically installs a successor baseline and rejects every predecessor publication. Model catalogs are renderer cache/presentation data: a silent `refreshModels` intent completes under its owner, then a same-owner `get_available_models` query may replace the cache. Failed refreshes retain the cache and record only an owner-scoped retry affordance. Renderer and main may send only high-level, owner-bound intents; they may not choose Pi abort targets, prompt-versus-queue admission, or another Pi semantic result.

Attach and resync are baseline-plus-replay operations. Main buffers publications for the renderer generation, requests a synchronous child read-barrier baseline, installs it at a high-water mark, then replays only the contiguous buffered tail. The read barrier bypasses long-running mutation ingress; mutations that land afterward advance source cursors into replay. Same-owner/same-generation requests are single-flight, superseded requests cannot mutate router state after their awaits, and a successor renderer generation inherits any bounded same-owner attach tail so its baseline cannot cover and erase an unseen user event. The renderer atomically materializes transcript events in the replay as well as reducing their cursors, so a first user echo emitted during attach cannot disappear while a later assistant event remains. The baseline includes the semantic snapshot, operation-journal watermark, extension-UI reconstruction state, transcript live-tail/overlap boundary, complete child-owned navigation presentations awaiting exact acknowledgement, any active Shell Turn reconstruction keyframe, and panel keyframes or explicit repaint requirements. Buffer overflow or a gap requests another baseline rather than pretending a current snapshot repairs continuity. ANSI chunks alone cannot reconstruct a panel: it is synchronizing and non-interactive until a framebuffer keyframe or acknowledged full repaint; state that Pi cannot reconstruct after child death is closed as unavailable.

Every mutation has a stable ID, expected owner, and child-written journal entry before possible Pi dispatch. Duplicate same-owner IDs with the same payload execute once; a conflicting reuse is rejected. Receipts report admitted/duplicate/not-admitted/delivery-unknown, while typed intent outcomes arrive in frames and alone update canonical operation state. The child's single ingress scheduler serializes intent **admission**, not completion: long-running compaction and bash operations open their admission barriers inside the serialized slot and then settle as deferred outcomes off-scheduler, so later compatible semantic ingress can keep flowing. Navigation is intentionally stricter. From `runNavigation` start, submissions may enter navigation custody, while other mutation intents are refused and already-reserved work rechecks the same fence before SDK execution. A successful navigation captures provisional branch escrow before releasing `runNavigation`, then terminal settlement marks that escrow attach-ready. Until transcript installation is acknowledged, other mutation intents, lifecycle replacement, and custody drain remain fenced; a submission may remain in navigation custody but cannot reach Pi. Bare ESC bypasses this scheduler through the direct owner-bound `session.escape` path, so a Pi prompt preflight cannot delay cancellation. It advances an admission generation before selecting the abort target; each prompt still before Pi's successful preflight callback becomes an independently reconcilable, non-replayable `outcome_unknown` restoration. A delayed idle callback throws before new-turn delivery. Pi rechecks streaming after awaited input hooks, so acceptance-time queue classification is recorded in the preflight callback rather than frozen when admission starts: an input hook that starts a turn can move an initially idle prompt into the streaming queue path. The bridge observes Pi's final public `ExtensionRunner.emitInput()` result without rerunning handlers; `continue` makes only the later exact raw append eligible for stable ownership, while handler-side-effect, transformed, and handled slots remain conservative unowned custody. An admission-context queue update seen before that result is non-owning evidence used only for queue classification and attachment custody. The cancelled callback always checks the requested public queue lane for late work and clears it when present. For streaming, an ordinary raw prompt with no input handlers, or with a final `continue`, can own only the exact one-slot append observed under its bridge admission context; the delayed callback uses public `clearQueue()` and excludes those attributed cancelled slots from generic restoration, while every handled, transformed, or otherwise ambiguous cleared slot is preserved conservatively. Other successfully cleared entries are `not_processed`, and all cancelled intents retain separate restorations and attachment custody. Later app submissions remain behind the admission fence until cleanup settles. If cleanup fails, the authority permanently fences custody, lifecycle replacement, and queued or new semantic dispatch until main retires the child. A lost post-dispatch settlement is likewise permanently `outcome_unknown` recovery custody and is not replayed against a successor. Observed operation records cover agent, retry, bash, navigation, command, and compaction state machines; a compact command invocation is `command`/`invoking` plus a conservative barrier, never a fabricated compaction start. Bounded journal and dispatched-intent retention expose independent low/high watermarks and truncation without retaining terminal payload/image bytes or claiming coverage before a truncation watermark. Tree navigation's complete active branch is excluded from retained outcomes and journal replay: retained semantic state keeps only target/leaf/status metadata, while child-owned presentation escrow crosses in the live fast path and survives detach/gap attach until exact acknowledgement. While that escrow is pending, its compact terminal intent record is exempt from both age pruning and capacity eviction so attach always retains the metadata needed to validate the branch.

Replacement freezes child semantic ingress, obtains a main advisory-lock permit for the target, then publishes one terminal successor frame before predecessor routing is released. Lock contention rejects mutable activation; the advisory lock coordinates cooperative Pi-Vis owners and is not a security boundary. This keeps old-owner frames and delayed outcomes from changing the successor projection.

The identity/epoch, snapshot sequence, lease/resync, dispositions, revisioned editor, generation/UI acknowledgement, panel sequence, and transition-batch protocols remain supported only as compatibility diagnostics or explicit-baseline bridges. They are non-authoritative: mixed records must never be presented as one cursor, repair a gap, settle a mutation, or overwrite the authority reducer. `RendererAuthorityState.authoritativeSnapshot` is the sole semantic projection while its semantic plane is `following`; on synchronization loss, retained authority data is `staleDiagnosticSnapshot`, controls are fenced, and it cannot fall back to a legacy snapshot. Semantic snapshots canonically carry `sessionName` (including a clear); rename outcomes do not derive it. Legacy mutation and presentation consumers are prohibited: no generic command channel, direct runtime snapshot, transcript event, receipt, returned promise, disposition, or lifecycle settlement may mutate canonical semantic state outside the child frame/reducer path.

## Submissions, custody, and irreversible presentation clears

All text/image work is submitted through `session.submit`. A submission names the expected host/epoch, editor revision, stable intent ID, queue mode, surface, original `inputKind`, transformed text, and images. The renderer classifies the raw editor value before prepending file paths or diff comments, so an ordinary prompt remains ordinary even when its transported text begins with an absolute `/path`; current host decisions about slash images, extension dispatch, queue ownership/replayability, and attachment consumption use that field. Every valid attempt receives a correlated disposition, including main-process lifecycle fences; malformed IPC is rejected as an error. `not_submitted`, `in_custody`, `admitting`, `consumed`, `rejected`, `extension_error`, `completed`, and `outcome_unknown` distinguish admission evidence from terminal authority-frame outcomes. `admitting` remains child-owned pending evidence, not a terminal unknown result. Before dispatch, Composer registers the exact ordinary-prompt draft and attached comment revisions in session-store custody as well as its mounted UI ref. Correlated acceptance clears only those exact renderer revisions and authoritative editor attachments even if session switching or sleep/wake unmounted Composer; a newer draft, attachment set, or edited comment is never cleared. That visible clear is an irreversible presentation commit: later rejection, outcome uncertainty, recovery, or queue settlement cannot reinsert the submitted revision. A refusal before the clear leaves the already-visible draft untouched.

Custody is FIFO. A compaction barrier drains eligible custody before later ingress after the barrier succeeds. Navigation retains the same FIFO prefix through both SDK settlement and presentation escrow; its custody drains only after the renderer installs and acknowledges the exact branch. Entering custody acknowledges and clears the source revision. Cancellation, failed navigation, interrupted queue delivery, and uncertain admission produce a child `queue_restoration` record with original text/attachments, every cleared intent ID, and certainty (`not_processed` or `unknown`). Those records are non-replayable outcome evidence, not draft payloads. Host queue snapshots and host-correlated delivered user events preserve ownership without using transformed text as identity.

Pi-Vis projects authoritative queues as pending work at the fixed transcript/dock boundary, above extension widgets and the Composer, not as transcript history. A queued ordinary prompt does not receive an optimistic user bubble; only Pi's later `message_start` creates the delivered user transcript block. `manageQueue` operations target stable GUI submission intent IDs and settle through the same authority-frame outcome path as every other mutation. Because Pi has only destructive public queue mutation, the host permits a whole-queue rewrite only for an exclusively Pi-Vis-owned, untransformed, attachment-free replayable plain-prompt queue. Nonempty replay additionally requires Pi's public extension runner to prove that no input hooks are registered. Under those proofs, the host clears both FIFO lanes, starts every public `steer()`/`followUp()` replay before awaiting any one result, and then requires the exact `queued` disposition for every item. Starting all calls in one JavaScript turn keeps Pi's per-call asynchronous input-processing boundary from exposing a partially rebuilt queue to the active agent while preserving lane order. A stable owned target may still be removed when that target is non-replayable, provided every remaining slot passes the whole-queue proof, because the removed payload is never reenqueued; clearing the complete owned queue remains safe because it performs no replay. Any unowned, pending-admission, changed, hook-active, or uncertain remainder is left untouched and reports a typed rejected/unknown outcome. The authoritative queue projection includes its available/unavailable safety reason plus exact target IDs for delete-only availability, so the renderer exposes only operations the host has proved safe. The renderer never mutates or optimistically reorders its local queue projection, and queued text is not editable in the UI.

The record is not a renderer action request. Main resolves it to the one-way, compatibility-named `session.restoreDraft` settlement event. Any record with `clearedIntentIds`, and every command-only record, resolves to `dropped` regardless of certainty or reconciliation failure. That resolution also fences captured host editor recovery so a predecessor primary cannot rehydrate after restart. A legacy/pre-clear record may resolve to `restore`, allowing already-visible host editor state to survive, but the renderer never synthesizes or merges record text or attachments into Composer. It applies each record ID once, retires only an exact pending correlation, leaves current text/attachments/comments/injections untouched, and calls `session.acknowledgeRestoration`. There is no restoration channel or card, restore/dismiss action, or user-selected acknowledgement lifecycle.

Persistence reconciliation remains available only for a genuinely pre-clear legacy checkpoint. Once dispatch/admission or custody records the clear, missing, malformed, unreadable, or inconclusive history cannot override it. A failed host's captured editor recovery suppresses the submitted primary while promoting any distinct newer conflict candidates in order. A post-dispatch `outcome_unknown` is permanently non-replayable across replacement and permanently absent from editor presentation; this may leave the text in neither transcript nor Composer, which is safer than silently recreating a prompt the user saw disappear. See [ADR 0004](../decisions/0004-silent-reconciliation-replaces-user-review.md).

## Direct Shell Turns

`runBash` is a stable, owner-bound foreground intent carrying the exact raw editor text and revision that produced its normalized command. The child recomputes the `!`/`!!` classification, rejects a stale or mismatched source, and validates the authoritative editor inside serialized ingress. It also refuses the turn before admission unless the session is directly idle: streaming, compaction, retry, Bash, navigation, active command work, pending Pi messages, submission/preflight custody, a transition, or another unsettled intent makes it `not_admitted`. It is never placed in prompt custody or a shell queue. Pi 0.99.2 `user_bash` preparation leaves the ingress scheduler while extension code awaits and re-enters it for owner/editor/busy revalidation plus start and receipt. The event is fail-closed: a thrown handler or invalid defined result aborts, and only `undefined` reaches the host PTY fallback. Escape can fence pending preparation as `not_admitted/cancelled`; the matching draft remains owned by the editor and a late handler result cannot cross the execution boundary. Admission is published and the renderer may clear the matching draft only after the chosen PTY or non-PTY path and the durable Shell Turn start marker succeed; a pre-start failure remains `not_admitted`, while a post-marker failure settles a visible failed turn. Admission opens one semantic `activity.bash` projection with execution ID, command, start time, context classification, and explicit PTY classification; input readiness and compact/fullscreen mode exist only for PTY turns. A second direct or compatibility Bash request in that session is rejected.

The correlated live block is a Shell Turn rather than a tool card. Raw `bash_terminal_data` leaves its bounded `terminalOutput` reconstruction keyframe immutable and appends exact, sequenced deltas to a separate bounded chunk queue on the transcript plane; Pi's `bash_execution_update` text is not mixed into that VT replay. This avoids rebuilding a one-MiB string for every output record while preserving exact xterm order. A terminal first consumes the unacknowledged, host-fenced keyframe already delivered by App's authority attach; it must not request a redundant second keyframe merely because that baseline caused the terminal to mount. The session records the renderer-local key only after its xterm acknowledges it. A later xterm remount that would reuse that consumed key requests a fresh authority attach through App's single-flight coordinator before creating xterm or enabling input. Every accepted keyframe increments a renderer reconstruction revision even when its output sequence is unchanged, while every actual host fence advances its own token. ACK must match that token and output sequence, so an equal-sequence remount still rebuilds without allowing a delayed predecessor ACK to release it.

During a recoverable same-owner semantic `synchronizing` fence, the renderer may retain the Composer-slot presentation only when the stale diagnostic Bash activity and the independently retained streaming PTY block name the exact same execution. This selector is presentation-only and must never authorize input, resize, Escape, or signals. The prior xterm remains mounted but frozen beneath a compact restoration status until a fresh attach, reconstruction revision, and acknowledgement restore control; an unavailable plane, owner mismatch, execution mismatch, or settled transcript block removes the slot immediately. This prevents Composer/terminal focus churn without weakening authority. Renderer detach likewise fences PTY input until the replacement xterm acknowledges its fresh reconstruction watermark. An active extension-supplied non-PTY turn instead attaches as a bounded normalized-output baseline with an independent update-sequence watermark; covered transcript replay is ignored and later updates append to the same execution block. Owner mismatch or semantic activity/id/PTY disagreement invalidates that attach baseline. The retained PTY snapshot also carries the original accepted-interrupt timestamp so switching away cannot reset the two-second force-stop deadline. Owner, epoch, execution ID, input sequence, and resize revision prevent predecessor input or layout from reaching a successor PTY.

Completion replaces transient VT replay with the normalized output from Pi's canonical Bash execution message and clears semantic Bash activity. `!` leaves that command/result eligible for Pi context; `!!` persists `excludeFromContext`, causing Pi 0.99.2 to skip the whole Bash execution message. The host appends `pivis.shell_turn_start` before spawning and `pivis.shell_turn_complete` after settlement to retain execution ID, cwd/start, duration, signal, and normalization metadata around Pi's message. History loading coalesces those records into one settled Shell Turn; an unmatched start rehydrates as interrupted with no spinner. Raw replay and terminal input are not persisted.

The SDK host remains the owner when the user switches sessions, so the process continues and only that session projects its activity. Returning uses the reconstruction handshake; completion in the background cannot become another session's turn. Reload/worktree replacement and narrow activation release are refused while public Bash activity is live. Host failure or forced disposal terminates the PTY where possible, and persisted unmatched-start evidence is presentation-only interruption recovery rather than semantic completion.

## Renderer generations, UI, and panels

Renderer attachment has a monotonic generation. Main asks the host to cancel old-generation blocking UI and only proceeds after its acknowledgement. An attach that crosses a cold or unresponsive host, closed IPC channel, session disposal, process replacement, same-process epoch replacement, or newer renderer generation resolves as typed unavailability, with full record/process/host/epoch/generation identity revalidated after cancellation and baseline awaits; already-issued Electron IPC cannot be revoked by renderer-side retry cancellation. Superseding a cancellation waiter retires it without letting its old timeout publish unavailability over the successful successor. A transport discontinuity rejects pending authority attachment immediately and retries only after its correlated state repair. Dialog answers and panel close requests carry operation ids and are acknowledged by the host. Panel input uses a per-panel sequence acknowledgement; main serializes each panel's in-flight inputs before validating gaps, and detected gaps are repair signals. Authoritative panel close/clear/reset events retire the renderer sequence key, so a replacement host may safely reuse its process-local panel IDs while ordinary same-host React remounts preserve sequencing. Composer/editor synchronization is revisioned: text plus unsent image/file attachment payloads are patched into host-owned editor state and survive renderer reload/close recovery. Renderer edits made while semantic authority is fenced remain one complete local text-and-attachment candidate; a same-owner recovery or successor rebases that candidate through the revisioned patch protocol, while a temporary absent snapshot never clears its attachment custody. Non-prompt command dispatch first waits for the revisioned patch that produced its editor text. Recognized commands carry a request id and captured host/epoch through IPC and are rejected rather than queued across replacement. Intent-shaped commands clear both the mounted Composer and authoritative editor on child admission; that clear is final — a later failed terminal outcome is a domain error surfaced through the transcript and toasts and never reinjects the command text. Native Composer submit/invoke actions retain correlated clearing behavior, while Unified Enter clears synchronously before renderer admission. In both surfaces the visual clear is final: no later refusal, failure, unknown outcome, restoration settlement, renderer remount, or host recovery may reinsert that submitted revision. For submits, the explicit original `inputKind` decides whether the exact accepted revision consumes attachments; transformed text is never reclassified by its first character. All clearing is fenced to the originating component instance, local edit generation, and current ready/available captured runtime. Effectful and replacement commands additionally retain an intent before dispatch. If child IPC rejects the command it settles `not_executed` and preserves input; if IPC accepted it but the host acknowledgement is lost it settles `outcome_unknown`, is never replayed, and publishes an acknowledged dropped-restoration outcome. Built-in picker continuations retain the runtime identity that opened the picker, including model changes, fork/scope/logout/trust commands, follow-up model-catalog reconciliation, and trust-triggered reload. `/reload` is identity-bound independently and main revalidates its captured host after the fresh admission snapshot before issuing the in-place reload. Composer-originated reload carries its exact editor revision/text; the child consumes only that unchanged command in the successor baseline, while picker/extension reloads and newer or conflicted editor custody remain intact. Input that never dispatches, conflicts during editor synchronization, or belongs to a stale unmounted completion is preserved. An empty initial editor injection cannot overwrite a non-empty pending-workspace or per-session renderer draft: Composer rebases that exact draft once to the attached authoritative editor (including its current replicated attachments) through `session.editorPatch` only, never submission. After an editor-patch transport failure, unchanged retry first fetches and validates a fresh authoritative runtime snapshot, rebases to its editor revision, and only then retries the patch. Accepted prompts tolerate the host's custody-clear revision advance but preserve later renderer edits and later host injections. Pending-session promotion migrates the workspace draft into the real session before retiring the workspace slot. The host decorates both queued and idle-direct authoritative user echoes with the stable submission intent at Pi's synchronous preflight boundary; session-store custody uses that identity to retire the exact dispatched draft/comments even while Composer is unmounted. The mounted Composer additionally fences visible text, attachments, and local edit generation. An exact untagged-content fallback remains only for legacy hosts. A dispatched ordinary prompt freezes the Composer input as "sending" (disabled textarea plus spinner) until host acceptance clears the text or an acceptance receipt/settlement arrives; the freeze is renderer component state only and never survives reload or restart. While compaction is active, the Composer stays typable but prompt-transport submissions (prompts, bash, a second compact) are refused with a brief self-clearing danger ring tint — deliberately not a toast and never a silent queue. Extension `setEditorText` and `pasteToEditor` mutate that same host revision; main treats their UI message only as a resync notification, never an unversioned injection. These extension mutations preserve unresolved conflict candidates and their attachment sets until explicit reconciliation. If a local patch is already in flight, the renderer suppresses replacement until the host reports acceptance or exposes both values in explicit Composer conflict presentation. Image reads acquire renderer custody synchronously before `FileReader` starts, so an attachment-only pending session cannot be reaped during the read and remains recoverable in the sidebar after switching away. Each read captures the session/editor generation; completion after a session or host change is discarded with a warning rather than attaching private data to the new context. Unified clipboard reads similarly capture panel/editor revision and text: an unchanged reply advances replicated editor state, while an intervening edit or retired TUI generation preserves the temp image as an attachment/conflict instead of silently merging it into a newer draft or dropping it. Submit is refused while a read is outstanding, and completion patches the current text ref rather than the text captured when the picker opened. A patch is accepted only from its base revision, otherwise the host returns the canonical text/attachments and conflict data. Rejection advances a local patch epoch: every already-queued optimistic patch is fenced, the revision rebases to the host, and only a subsequent user edit may explicitly reconcile the preserved versions. Unified-editor Enter captures the raw source revision and a frozen attachment snapshot, then immediately advances the authoritative editor to a new empty revision. The immutable pending source is replicated in main and host only for dispatch validation across renderer reattachment; it is never projected as current editor presentation, so newer typing and rapid subsequent submits remain available. Main gives a claimed request a bounded claim ID/deadline; expiry creates one non-replayable dropped settlement and stable-intent tombstone, releases source custody without injecting text, and fences every late renderer continuation or response. Admission validates the stable intent, source revision, and original `inputKind` before any Pi side effect rather than comparing transformed transport text with the newer current draft. A retired `(host, epoch, request id)` remains tombstoned for the session record, so a duplicate late host record receives a refusal instead of creating a new claim or intent.

The Input/Extension switch is an editor-custody handoff, not submission evidence. Input→Extension waits until the complete renderer draft and attachments are authoritative, then records one owner-bound renderer lineage. Extension→Input first performs a fresh authority attach: an untouched source remains available for native submission, while a TUI edit or clear retires only the matching persisted draft/injection/attachment generation before Composer mounts. Unified source receipts that beat their authority baseline are queued by owner and drained once that exact owner follows; their code-comment revisions are frozen at event time. Comment custody is durably persisted before active revisions are removed, with an empty replay tombstone even when the source had no comments; storage failure fails the submission closed and leaves comments visibly staged. Slash and Shell Turns retire command-text lineage while retaining a separate attachment lineage for the next ordinary prompt.

## Lifecycle

1. **Open:** `session.open` creates a registry record; history stays on disk until requested.
2. **Activate:** `session.activate` forks the SDK host and acquires the advisory lock. For a pathless new session, the child discovers the SessionManager file and waits for an `initial_session_file_permit`; main must reserve that exact file before initial extension binding or ready/following publication. Contention is a hard startup failure. Main pauses its pre-ready watchdog for correlated dialogs/custom panels while retaining a longer bounded human-response deadline. It then receives initial binding records plus their terminal direct snapshot in one ready commit before becoming available. If asynchronous environment/worktree discovery yields while the renderer closes the cold record, main rechecks the registry immediately before activation and treats the stale request as a silent no-op. A startup failure is failed/unavailable; there is no alternate runtime.
3. **Run:** snapshots and host records keep queue, liveness, catalog, and editor state current. Every awaited command disposition/completion publishes a fresh direct snapshot; asynchronous prompt preflight and terminal settlement each publish their own boundary. Extension UI and panel records preserve host ordering. Lifecycle watchdog time is suspended only by dialog/custom-panel promises opened in that lifecycle operation's async context; unrelated persistent UI cannot wedge a transition. Extension command-context `newSession`, `fork`, and `switchSession` actions use the same replacement transition/fatal-boundary path as renderer commands. Every replacement takes a fresh direct snapshot and refuses to begin while unrelated SDK work, submission admission/prompt fences, custody, or another host command remains active. A supported extension command-context replacement carries its owning submission intent through async context and may exclude exactly that one admission—never unrelated intents, commands, custody, navigation, or compaction—from the guard; `waitForIdle` polls the fresh public session getter under a bounded deadline. Host command ingress is synchronously counted and rejected once a transition starts, closing the before-dispatch/transition race. Reload is admitted only after main obtains an available correlated idle snapshot and the host rechecks fresh idle/submission/custody getters immediately before starting its transition. Full-state probes wait for transition settlement rather than exposing provisional snapshots, and invalidation/reload cancel dialogs that belong to the retiring extension generation. Provisional blocking dialogs and custom panels create main-process control-watchdog and registry snapshot leases that end only on host acknowledgement, panel close, or atomic transition commit—not merely when main sends a response—so normal human think time and delayed host processing are not misclassified as host silence. The correlated lifecycle command/reload deadline is suspended by the same lease and resumes with only its unspent active-execution budget.
4. **Transition/reload:** runtime replacement is an epoch transition. Before replacement work begins, the host emits a sequenced transition-start boundary; main immediately publishes `transitioning`, and host admission independently returns `not_submitted` while the transition exists. Cancellation stages its old-epoch full snapshot while availability remains `transitioning`, then emits a correlated settlement boundary that atomically restores available old-epoch state. Terminal transition batches must match both the pending transition ID and its announced provisional epoch, and the terminal snapshot must be fresher than prior same-host state; malformed, unsolicited, stale, or regressed batches cannot clear the transition fence. Submission terminal records retain their immutable admission host/epoch. A forced predecessor settlement is emitted on the live transition channel rather than folded into the successor batch; main converts it to non-replayable `outcome_unknown` recovery evidence and never publishes it as successor completion. Editor custody and asynchronous editor-patch acknowledgement both revalidate record, process, host, epoch, availability, and transition state after awaiting, so even a forced late predecessor settlement cannot be attributed to or clear successor state. Before successor binding, the host resets presentation owned by the retiring extension generation—statuses, widgets, title/working overrides, and terminal-input listeners—while preserving notification history, capability diagnostics, and revisioned editor custody. The host buffers transition-sensitive records and emits them with one terminal snapshot. Main commits that batch atomically for transport diagnostics; renderer semantic and presentation recovery installs the successor exclusively through authority publications or a serialized authority attach. Compatibility batch records never repair or overwrite an authority plane. Reload is refused while the direct snapshot is non-idle.
5. **Failure:** main fences the old host state; resolves and cancels old-host UI acknowledgements; dismisses dialogs; clears panel maps, checkpoints, input chains, and renderer panels; marks uncertain retained work `outcome_unknown`; retains the last meaningful authoritative editor checkpoint and the last child-authored runtime-resume checkpoint while recovery is attempted; and can make up to three short backoff-delayed SDK-host restart attempts in one 30-second crash window before stopping the loop. The resume checkpoint is returned only to this record's replacement host and cannot be sourced from another session or from a stale direct snapshot. Before a planned respawn, main first requests a fresh correlated snapshot and repeats every idle/custody/retained-work eligibility check immediately before detach; before publishing any replacement host's initial batch, it rehydrates retained text/attachments and recreates conflict state. If that replacement fails during its remaining activation setup, main recaptures the replacement-owned validated editor before another bounded retry, and one physical failure consumes only one crash-loop attempt. Rehydration validates the editor disposition and retries against a concurrently advanced replacement revision rather than treating transport success as acceptance. If bounded retries all conflict, the live replacement remains authoritative and the old checkpoint—including attachments—stays as its explicit conflict candidate; successful recovery likewise retains replacement-side text and attachment objects as conflict candidates. Runtime editor conflict state can carry alternate and additional text-and-attachments candidates so pre-existing checkpoint conflicts are not collapsed when recovery introduces another candidate. Candidate identity is the `(text, attachments)` pair, so equal text with distinct files/images remains separately selectable, while candidates identical in both fields are shown only once across authoritative, local, retained, and replacement state. The renderer independently preserves any newer local draft or staged attachments that had not yet reached main. If the replacement also carries an older host conflict, conflict presentation keeps three distinct candidates—the actual renderer draft, authoritative replacement text, and retained alternate—rather than selecting the wrong value. No old-identity UI operation can time out against the replacement host. Renderer editor patches, dialog responses, and panel input/resize/close carry the host instance and session epoch captured by their originating surface; main rejects them if either identity no longer matches, including when numeric panel IDs or editor revisions are reused. Panel render effects and input/acknowledgement sequence maps are keyed/reset by the full `(hostInstanceId, sessionEpoch, panelId)` identity, so even an old passive effect firing during a coalesced same-ID replacement cannot consume the new panel's first sequence. Planned worktree respawn applies the same UI retirement before detaching the old process and refuses to move while authoritative or retained work is active.
6. **Close:** `session.close` immediately fences normal ingress in main. If a live streaming host exists, main gives one best-effort ESC a bounded wait, then uses the private force-close protocol when possible. Cold, failed, missing, and unresponsive hosts take the same silent disposal path. Planned retirement disconnects IPC first; the child closes publication/shell resources and awaits public runtime disposal, with a four-second child fallback. Main waits 4.5 seconds before SIGTERM and three more before SIGKILL. The registry awaits actual exit and asynchronous advisory-lock unlock before removing the record, including the compensating unlock when acquisition itself races shutdown, so a successor cannot overlap a retiring authority or inherit a late stale lock. App-wide quit marks every record dead through one shared `stopAll()` promise and prevents the first Electron `before-quit` until that drain settles; re-entrant quit events reuse it. An 8.5-second outer deadline prevents an impossible-to-reap process from trapping Electron forever. Persisted session files and worktrees remain on disk. There is no renderer confirmation, close token, or cancellation path.


There is no fixed active-host cap and no generalized idle/LRU eviction. A renderer activation visit carries a unique token only when it causes a cold→live transition. Switching away within the two-second startup-cancellation window may release that exact token: main handles a release that races Pi discovery, waits for startup if necessary, takes a fresh direct snapshot, and retires the host through graceful disposal only if the visit had no user interaction and all submission, queue, editor, command, restoration, transition, dialog, panel, extension-published status/widget/working, and acknowledgement state is empty. The release-before-activation tombstone uses the same two-second expiry, so a delayed or failed discovery cannot retain cancellation state indefinitely. A pre-existing or older host is never assigned to the visit, returning cancels an in-flight release, and an unsafe release is abandoned rather than retried as a broad idle policy.

## Workspace search isolation

Workspace search is persisted-history-only and is not a second runtime authority. A disposable worker index may catalog JSONL for a currently registered workspace and known worktrees, including all saved branches and pre-compaction history, but JSONL supplies results and exact context. Querying and read-only preview do not touch `SessionRegistry`, activate a host, or change active workspace/session, branch, transcript, draft, attachments, editor revision, unread state, or runtime identity. Context is occurrence-exact and reports `ready`, `relocated`, `changed`, `removed`, `forbidden`, or `unavailable`; it never substitutes changed content.

Only explicit result opening enters normal stored-session opening and its activation-visit lifecycle. There remains no fixed active-host cap or generalized idle/LRU policy; search cannot reap a pre-existing host. See [workspace session search](session-search.md).

## History and transcript

Session discovery and complete history hydration read persisted JSONL asynchronously. Main converts histories cooperatively, yielding between bounded batches, and coalesces concurrent requests for the same canonical file path through cache publication (so settlement cannot open a duplicate-parse window). A cold saved-session open reconstructs and selects its renderer record immediately, starts identity-less persisted hydration, and fences subprocess activation behind that hydration. Thus saved transcript content and the authority-independent textarea are available before attach begins; runtime-backed actions remain fenced until semantic authority follows. Initial hydration waits for an idle runtime and retries if the live transcript changes during the read, preventing persisted/live overlap from duplicating or overwriting racing events. Persisted transcript hydration walks the complete active on-disk branch across compaction markers: compaction limits the model's active context but does not remove earlier GUI scrollback. Main caches only a small LRU working set of converted complete histories so multiple large sessions do not remain resident indefinitely. A growing-file cache miss re-parses only during an idle re-hydration; sequential misses are bounded by those re-hydrations. Every `session.loadHistory` request carries the expected file, renderer history generation, and explicit host/epoch fields: a live runtime supplies both values, while an explicitly cold owner supplies a required `null`/`null` pair. Main admits the cold-owner form only for a non-activating record with no process or runtime identity. For live reads it requires ready/available, non-transitioning host/epoch identity, captures the actual registry record, process object, file, host, and epoch before file I/O, and validates the same lifecycle owner afterward; cold reads are therefore invalidated if activation begins before or during I/O, and live reads are invalidated as soon as transition starts. The renderer independently increments history ownership on file adoption, history seeding, and host/epoch replacement, and applies the complete history only while generation, file, and runtime identity still match. Initial open retries only after a store subscription observes a concrete live owner (or a genuinely new cold generation); it never retries an unchanged cold-owner request on an arbitrary short timer. Once ownership is stable, hydration waits for idle and rereads whenever the transcript changes during I/O. Each ownership/idle wait has a bounded timeout, and terminal failed/exited state ends the wait. The transcript reducer turns Pi events and persisted entries into blocks, including custom entries, cache notices, system messages, append-only context edits, and usage records. Its live and persisted projections retain Pi's complete ordered raw tool-result content (including interleaved parts and extension-owned part fields) alongside text/image conveniences, arbitrary details, and Pi-attributed usage/cost. Live results additionally retain fields such as `structuredContent`, while persisted `ToolResultMessage` deliberately does not; live nested events retain parent IDs, and the persisted parent result retains the bounded `{ calls, complete }` record. Custom messages likewise retain raw content alongside text/images/details/timestamps. Standalone Bash fields, raw custom-entry data, live compaction token estimates, and compaction/branch-summary usage also survive their applicable paths. Retain-none compaction is persisted as a self-referential string `firstKeptEntryId`, never a nullable boundary, and branch summaries remain distinct from successful compaction markers. Pi 0.99.2 direct Bash updates are correlated by execution ID between host-authored start/end records; default PTY and extension-handled non-PTY turns both settle as one visible user-authored Shell Turn. Assistant messages retain additional passthrough fields such as `rawStopReason`, `endTurn`, and deferred-request handles, while tool calls retain optional namespaces; the `deferred` stop reason is not classified as a provider error. Valid assistant lifecycle/tool-call stream subevents remain typed transcript-plane traffic even when they require no direct visual mutation; only genuinely unknown top-level events are dropped and mark presentation dirty. Successful compaction moves the live block array by reference into immutable archive chunks and starts a small mutable tail at the marker; complete hydrated history is also retained as an archive chunk. The renderer owns that complete archive immediately, but mounts its presentation automatically in bounded newest-first React/DOM chunks, preserving the reading anchor as earlier chunks are prepended. This is cooperative presentation—not pagination or viewport virtualization—and prevents a single full-archive commit from freezing the renderer. Shared `FadeText` geometry is measured in one read-then-write frame batch so large transcript mounts cannot create per-label forced-layout cascades. Normal renderer per-token copies and reconciliation remain confined to post-hydration or post-compaction live-tail work; the SDK host retains the in-flight attach checkpoint as chunks and materializes its cumulative direct-SDK Pi message only at the attach read barrier. It is intentionally separate from runtime authority: history loading, tree navigation, and transcript rendering cannot overwrite a current host snapshot.

A persisted tool call without a matching tool result is an interrupted turn, not live work: idle-gated hydration and settled-branch navigation guarantee that such a call cannot still be running. History conversion settles the block and flags it `interrupted`; renderer history seeding defensively forces tool/bash streaming presentation off, and an unexpected terminal host status marks any still-streaming live tool/bash blocks interrupted. These are presentation flags only and never synthesize JSONL entries or semantic completion.

The working row also projects authority-gated compaction activity without widening model-streaming liveness. Active/unknown-origin, cancelling, and retry-wait compaction states render their current phase only while the semantic plane is `following`; synchronization fences therefore cannot leave a stale compaction status visible. The title-bar context meter refreshes on `agent_end`, `compaction_end`, and completed summarized navigation outcomes (plus its slow safety poll), so tool, compaction, and branch-summary usage updates do not wait for another model turn. Persisted-history reconciliation is likewise presentation-only: rejected transcript-plane entries mark the session dirty, and a completed observed compaction lacking a materialized compaction block schedules one bounded, idle-gated re-hydration per operation. The reusable hydration path retains file, owner, epoch, generation, idle, and transcript-change fences, so repair from authoritative JSONL cannot overwrite a current host snapshot or become a semantic liveness source.
