# Processes and IPC

## Process model

```
Renderer (React)  ⇄ typed Electron IPC ⇄  Main process  ⇄ child IPC ⇄  SDK-host AgentSession
```

Each active session has exactly one live authority: a `SessionHost` fork of `resources/pi-session-host/host.mjs`. The host imports the bundled pinned pi public SDK (`src/main/pi/pinned-pi.ts`), creates the `AgentSession`, uses Pi 1.0.0's public `ModelRuntime`, runs extensions and pi-tui surfaces, and owns command admission and state snapshots. Public codemode, tool-search, and MCP factories are injected as replaceable built-ins; their native provider/tool metadata stays inside Pi rather than being reconstructed by Pi-Vis. [ADR 0006](../decisions/0006-pinned-llama-private-extension-exception.md) is the sole import exception: one exact-version adapter selects Pi 1.0.0's `llama.cpp` built-in factory, after which the ordinary public `extensionFactories`, provider, command, auth, and Pi-TUI paths own the integration. Before constructing an established runtime, it reads the active branch through the public `SessionManager`: explicit per-session model and thinking changes are passed into runtime creation even when that branch has zero messages. On every runtime-factory invocation it also resolves saved `enabledModels` through Pi's public diagnostic resolver and passes the result into construction, so extensions receive the actual scope through `ctx.scopedModels` at `session_start`. A genuinely fresh session starts with the saved default when it is in scope or the first scoped model otherwise; persisted branch identity and a resolvable non-null same-session resume model retain precedence. A null resume model deliberately uses Pi's scope/settings fallback while its thinking level remains owner-local. Direct snapshots also project `AgentSession.getAvailableThinkingLevels()` so renderer controls use Pi's current model/provider constraints. Each authority frame carries a child-authored runtime-resume checkpoint; main may retain and return that checkpoint opaquely only to a replacement host for the same session record, so an unpersisted initial model/thinking selection does not inherit another session's later Pi settings default. Persisted active-branch metadata has precedence, and a model override is used only while the public runtime still resolves it with configured auth. A genuinely new session with no resolved scope, or an unavailable persisted model, keeps Pi's normal settings fallback. There is no `pi --mode rpc`, experimental `PiClient`, or JSON/RPC session fallback.

Main owns process lifecycle, session-file advisory locks, IPC validation, activation-visit retirement, and forwarding. The renderer owns presentation and sends typed requests through preload; it never reads Electron APIs directly. Main-to-renderer notifications are best effort across window teardown: every send rechecks both `BrowserWindow` and `webContents`, contains the final `send()` race, and never lets a disappearing render frame crash main. An unexpected renderer `crashed`, `oom`, or `abnormal-exit` gets exactly one automatic document reload per window; a repeat or a non-reloadable exit is written to `diagnostics.log` and surfaced through a native terminal error instead of entering a reload loop.

External web navigation crosses the typed `app.openExternal` boundary and never navigates the privileged renderer. Both renderer affordances and main independently normalize an absolute, credential-free HTTP or HTTPS URL before main hands it to Electron's `shell.openExternal`; relative targets and every non-web scheme remain inert. BrowserWindow new-window and navigation interception use that same main-owned policy so an anchor cannot bypass the typed-handler validation.

Cold activation shares one login-shell capture; once its child is created, the capture has a five-second deadline and one-MiB output bound, and relative `SHELL` values are never PATH-resolved. At its deadline main closes capture pipes and rejects before later-turn best-effort tree cleanup, so inherited descriptors cannot strand startup. Node selection similarly shares one non-interactive lookup/version operation with a five-second aggregate budget, preserves the PATH-selected version-manager shim for the workspace-cwd host fork, and retries failures on the next call. Windows lookup/cleanup utilities come only from drive-qualified `SystemRoot\\System32` paths. Shell and Node failures emit sanitized diagnostics without captured output or environment values.

Main initializes a synchronous, best-effort `<userData>/diagnostics.log` before creating windows or hosts. It records main-process `console.error` output and fatal exception stacks without suppressing Node's default crash behavior, renderer error-console/preload/process-loss diagnostics, Electron child-process loss, and each SDK host's stderr plus exit/error context. Host stderr is persisted as it arrives, so an uncaught host exception survives after the child exits. The text log is capped at approximately 5 MiB and rotates once to `diagnostics.log.1`. Electron Crashpad also remains enabled locally with uploads disabled; native main/renderer/GPU crashes may have a minidump in Electron's `crashDumps` directory when no JavaScript stack exists.

## Workspace session search

Workspace saved-session search is a separate typed, generation-fenced renderer→main→worker path. Its worker catalogs validated persisted JSONL, maintains a disposable SQLite index, and serves workspace/worktree-scoped queries and exact read-only context. It does not call the SDK host or `SessionRegistry`; selecting/previewing a result creates no host or runtime side effect. Opaque targets are scoped to their renderer/workspace, and late batches/context are fenced. Only explicit **Open session** revalidates a target and delegates to the ordinary stored-session open plus activation-visit lifecycle. Thus search adds no process cap, idle/LRU reaper, or ability to retire a pre-existing host. See [workspace session search](session-search.md).

## Pi 1.0 auth and model-operation boundaries

Provider enumeration stays a read of public `ModelRuntime` metadata. Its typed
response adds only the bounded `oauthKind: "account" | "subscription"`
presentation classification; credentials and provider implementation objects
remain in the SDK host. The owner-bound `loginProvider` intent continues to
carry only provider and method. Its terminal result may additionally carry the
bounded Radius MCP status `unchanged`, `declined`, `configured`, or `failed`.
The status describes post-login global configuration and never changes whether
Pi committed the credential.

For Radius OAuth, the child first reads global `mcp.json` to decide whether
setup is needed, then the blocking extension-UI interaction asks for consent
before any write. The write and its lock stay entirely in the
SDK host. Only a same-owner `configured` terminal outcome allows the renderer
to request the ordinary typed `reload` intent; every await rechecks the captured
runtime identity, so a delayed predecessor outcome cannot reload a successor.
No file content, token, parse error, or lock detail crosses child IPC. The
Anthropic headless copy-code path uses the existing bounded `auth_url` and
`manual_code` extension-UI records, preserving only presentation context while
the prompt is live.

Codemode image generation remains a public nested model operation rather than
a new Electron command. Pi returns ordered image content and usage through the
ordinary tool-result/session event surfaces; the typed Pi protocol preserves
those blocks through authority, history, and transcript projection. Likewise,
MCP authorization-server discovery, issuer validation, credential keying,
scope step-up, and reconnect remain internal to Pi's public ResourceLoader/MCP
runtime. A hidden SDK-host extension bridges constructor-time deferred-loadout
restoration by reading public session context and calling public extension tool
APIs after reconnect on non-reload startup/resume. It gives pending definitions
one next-prompt reconnect opportunity, while Pi's native ResourceLoader owns
reload carry-forward. It persists no parallel loadout and creates no app-owned
secret or tool-state IPC.

## Direct Shell Turn execution and PTY path

Every direct Shell Turn is prepared in its owning SDK host through Pi 1.0.0's public, fail-closed `user_bash` event. A handler can return a complete non-PTY result or replacement `BashOperations`; only `undefined` from every handler uses the host's custom PTY adapter backed by `@homebridge/node-pty-prebuilt-multiarch`. A thrown handler or invalid defined result aborts instead of falling through to a shell spawn. Pi still owns canonical Bash persistence and cancellation through public `AgentSession` methods. Slow hook preparation is cancellable and runs outside serialized ingress; its result must re-enter the authority scheduler and pass fresh owner/editor/foreground checks before either execution path can start. The PTY execution freezes `SessionManager.getCwd()` and the SDK-host environment at admission, adds terminal capability variables, and does not let an in-command `cd` mutate session cwd. A host-side xterm emulator consumes raw VT output, tracks primary and alternate screens, and gives only normalized final text to Pi. Each retained alternate-screen interval contributes one final plain-text frame; the aggregate is capped at one MiB and a counted marker replaces omitted older or oversized frames. Raw control sequences and terminal input never enter Pi context. Pi's legacy stdin shell transport runs through one pre-parsed, readiness-marked compound bootstrap so an interactive `read` cannot consume a queued `exit`; bootstrap echo is never published.

Raw terminal deltas are bounded presentation traffic on the transcript plane, separate from semantic Bash activity and the operation journal. The host retains at most 10,000 emulator rows and one MiB of raw replay. For same-host PTY reconstruction it serializes terminal modes, cursor, primary/alternate buffers, viewport, and as much scrollback as fits in that bound, then appends any sequenced raw tail; raw replay with an explicit gap is the fallback if serialization cannot fit. Authority attach may instead describe an active non-PTY replacement-operations turn with at most one MiB/512 retained normalized-output chunks and an independent `bash_execution_update` sequence watermark. The renderer installs that baseline into the matching execution block, ignores replay at or below the watermark, appends later updates, and visibly marks an omitted prefix until the canonical end replaces the reconstruction. Both snapshot variants carry the exact owner, and a non-PTY baseline must match semantic Bash id/PTY classification. A PTY keyframe additionally carries dimensions, input sequence, resize revision, mode, bounded ANSI, accepted-interrupt time, and an omission flag. Every actual PTY reconstruction fence receives a host-issued monotonic token. Every replacement terminal obtains one shared App-coordinated fresh attach, installs that exact keyframe and retained tail, and acknowledges the exact token plus output watermark before queued xterm input is released; equal output sequences advance both the host fence token and renderer reconstruction revision and do not bypass the refresh. A delayed predecessor acknowledgement therefore cannot release a newer equal-sequence fence. A recoverable same-owner semantic gap may keep the exact matching prior terminal surface mounted as frozen presentation, but a gap in any authority plane fences input, resize, Escape, and signals until the new reconstruction is acknowledged. Mismatched or unavailable ownership tears the surface down instead of falling back to transcript liveness. The SDK host pauses node-pty while the emulator parser or child IPC channel is backpressured. Live model `message_update` publications carry only the incremental assistant subevent plus role; the host retains growing text, thinking, and tool-argument content in a chunk-backed form and materializes one complete cumulative message only when an attach read barrier requests its checkpoint. Transcript-only updates do not emit unchanged complete semantic frames. If main must rewind covered transcript traffic so non-stream records remain replayable, it retains the checkpoint's original source high-water; the renderer applies that covered lifecycle prefix, installs the cumulative assistant once, then applies only the later tail. This keeps model streaming traffic linear instead of retransmitting the growing response and semantic snapshot on every token. The IPC FIFO is bounded to 8,192 messages/eight MiB and fails the host rather than dropping a sequenced authority publication on overflow.

`session.shellInput`, `session.shellResize`, `session.shellReconstructionAck`, and `session.shellSignal` are owner-, epoch-, and execution-fenced; reconstruction ACK additionally requires the exact host-issued fence token and output sequence. Input is serialized with cumulative sequence acknowledgements and a 64 KiB record cap; resize accepts only increasing revisions and is clamped by the host to 20–500 columns and 2–200 rows. The viewport exposes no Stop/Force-stop chrome: focused Ctrl+C reaches the PTY as ETX through `session.shellInput`, while the fenced signal path remains available to host-owned interruption and cleanup flows. Switching sessions does not replace the owning host, so its Shell Turn continues there; in-session runtime replacement is refused while Bash is active. An explicit session close, timeout, or other host disposal force-terminates the PTY rather than detaching a background process.

## Deployed authority-frame protocol

[ADR 0003](../decisions/0003-authority-frames-and-plane-synchronization.md) is the deployed protocol. Its guarantee is **exact as of cursor**, not exact at the present instant: a `following` renderer plane has applied every complete publication through its named `(hostInstanceId, sessionEpoch, transportSequence, snapshotSequence)` cursor. A mutation can still be in transit after that cursor. Silence, a lease, a returned IPC promise, a receipt, or a transcript event never proves idle, cancellation, settlement, or success.

The compatibility snapshot/resync, transition-batch, disposition, and UI/panel acknowledgement paths remain available only to diagnose or bridge older surfaces at an explicit authority baseline. They are non-authoritative: they must not update canonical semantic state, repair a plane, complete a mutation, or be combined with a frame as one cursor. Legacy mutation and presentation consumers are prohibited: renderer and main dispatch high-level intents and render authority projections; neither may consume direct runtime snapshots, transcript events, receipts, returned promises, or legacy lifecycle/command settlements as semantic authority.

The SDK host is the `SessionController` semantic authority. It serializes mutations, records an immutable stable intent before crossing a possible Pi-consumption boundary, deduplicates same-owner/same-payload intents, rejects an ID reused with a different payload, and publishes typed terminal outcomes. `refreshModels` is one such mutation: it calls public `ModelRuntime.refresh()` and emits only a bounded completion outcome; it never returns a catalog in that outcome. Pi 1.0.0's `{ aborted, errors }` result completes only when it is not aborted and has no provider errors; error objects stay inside the child. After a same-owner completion, the renderer performs the separate owner-fenced `get_available_models` read. Main may fence for transport, owner, advisory-lock, trust, close, or lifecycle reasons, but does not choose abort targets, prompt-versus-queue admission, or any Pi semantic result. Renderer invokes an intent and uses the receipt only for delivery/admission feedback; canonical semantic state and outcomes are reduced only from authority frames. An admitted or duplicate receipt is not completion. Possible dispatch with lost settlement is `outcome_unknown` and is never automatically replayed across a replacement.

Extension Markdown transformation is an owner-fenced read, not a transcript mutation. The renderer batches currently visible user, assistant, and thinking strings with message type, streaming state, and available width; the child runs the public extension transformer chain and returns display-only strings. Extension functions never cross process boundaries, and transformed text never replaces authority events, persisted history, or model context. A stale owner or failed transformer falls back to the raw display text.

A semantic authority frame is one ordered child publication containing its owner, transport sequence, frame ID, ordered semantic records, and one complete terminal semantic snapshot. Main routes that frame without splitting it into independently committed semantic updates. Duplicate/older frames are ignored; a missing sequence moves the **semantic plane** to `synchronizing`, retaining any prior values only as visibly stale diagnostics until a baseline is installed. A successor owner baseline is installed atomically, so no predecessor record can modify it.

Attach and gap repair use a baseline/replay handshake rather than treating a fresh snapshot as enough: main buffers publications for the attaching renderer generation; the child serializes a synchronous read-barrier baseline; main installs that baseline at a publication high-water mark; then it replays the contiguous buffered tail. Baseline serialization never waits behind prompt, command, or other mutation ingress: JavaScript run-to-completion supplies the coherent point and later mutations advance source cursors into replay. Main coalesces concurrent requests for the same generation/owner and fences a superseded request so its late result cannot detach its successor; a higher renderer generation inherits the bounded same-owner transcript tail instead of clearing events that its cursor-only baseline cannot reconstruct. Renderer reduces replayed transcript payloads in the same atomic attach boundary instead of advancing the cursor while dropping their visible user/assistant events. Only after the baseline and contiguous replay is that plane `following`. The child baseline also repeats complete, unacknowledged navigation-presentation branches even though retained semantic outcomes and the operation journal stay compact. The renderer retires one only through the typed `session.acknowledgeNavigationPresentation` request, which main and `SessionHost` route to the exact current host/epoch and intent; the child acknowledgement is idempotent for a lost response. Presentation acknowledgement does not gate the semantic plane's already-installed `following` state. Bounded-buffer overflow, a gap, or a failed baseline stays `synchronizing` or becomes `unavailable`; unrelated traffic cannot repair it.

Synchronization is per presentation plane: semantic control, transcript, extension UI, and each panel have independent cursors and states (`following`, `synchronizing`, or `unavailable`). A panel repaint must not make an otherwise current semantic snapshot unavailable. Transcript attach combines a persisted-history cursor, live-tail cursor, retained streaming-message snapshot, active Shell Turn keyframe when present, and explicit overlap boundary; every live event is sent only on that sequenced plane and never as semantic liveness. Extension UI attach returns reconstructable dialogs (including operation/generation/pending acknowledgement state), status, widget, and notification state; subsequent requests use the same sequenced plane. Only messages discriminated as `extension_ui_request` may enter that typed plane: host-private Unified-submit, clipboard-read, and editor-custody requests remain ordinary owner-sequenced messages even though the UI context uses the same outbound callback. ANSI panel chunks are not reconstructable: attach requires a serialized child-owned framebuffer keyframe or a reset/full-repaint acknowledgement, and panel input remains fenced until the acknowledged keyframe publication. Unsupported extension-private panel state closes as unavailable after host loss.

Renderer-to-main `session.respondToUiRequest` ingress is schema-bounded before
main applies the separate owner, renderer-generation, host, epoch, operation,
and pending-request fences. Every response variant is strict (unknown keys are
rejected); `id` and optional `operationId` are each limited to 128 UTF-8 bytes,
and a text `value` is limited to 64 KiB of UTF-8. This includes provider API-key
and manual-code responses: credential values stay short-lived and cannot reach
child IPC, Pi, or the credential store until both validation layers accept the
response.

The child maintains a bounded operation journal with explicit low/high watermarks and truncation. It records observed operation boundaries (including compaction start/end and summarization retry wait/attempt transitions), intent outcomes, and anomalies. A detached attach can therefore show a current inactive state plus recent completed operations, but must never imply history before the low watermark. Getter/event disagreement is resolved inside the child conservatively: for example, compaction custody stays open while either the direct getter, observed span, summarization backoff, or admitted invocation barrier is open. Child failure produces no synthetic end; any possible terminal result is `outcome_unknown`.

Replacement paths use a lock-permitted transition: the child freezes semantic ingress and emits `transition.prepare`; main validates the target and reserves/acquires the advisory lock; the child performs the Pi transition only after that permit; then one terminal successor frame commits routing and releases the predecessor lock. Lock contention is a mutable-activation failure, not a warning. A `proper-lockfile` compromise callback for either the primary or reserved successor lock is terminal: main synchronously fences availability and ingress, invalidates the transition permit, detaches/stops the host, and never admits or restarts that record. Advisory locks prevent accidental competing Pi-Vis ownership, not malicious or lock-ignoring processes.

The authority-frame path is end-to-end: child serialization and journal, main buffered per-plane routing, and the renderer authority reducer are the semantic path. Compatibility records may be retained for diagnostics or explicit-baseline bridging, but no caller may treat a mixed legacy/frame update as instantaneous or combine it into one semantic version. Do not reintroduce legacy mutation/lifecycle consumers, generic command dispatch, or presentation reducers that use snapshots, events, or settlements as a fallback when an authority plane is synchronizing or unavailable.

## Compatibility diagnostics

The host still publishes direct `AgentSession` snapshots rather than synthetic liveness events. Each snapshot includes:

- `hostInstanceId`, `sessionEpoch`, and increasing `snapshotSequence`;
- direct `isStreaming`, `isIdle`, compaction, retry, bash, model, session, and queue values;
- host facts (submission, navigation, dialog, and custody state), extension catalog, and revisioned editor state.

Main rejects stale identity/epoch/sequence data. These snapshots and their transport availability leases are compatibility diagnostics, not a semantic projection. Snapshots have short availability leases (shorter while non-idle); expiry, an invalid envelope, or a real transport sequence discontinuity marks runtime state unavailable and requests a full resync. Ordinary control silence first starts one correlated full-snapshot probe and becomes unavailable only if its two-second deadline expires; polling jitter is not called a sequence gap, and identity retirement waits for eight seconds of continuous silence. The silence watchdog is suspension-aware: a large gap between its own ticks means the whole main process — and equally the host child — was frozen by system sleep, so on wake it resets the silence baseline and lets an ordinary probe re-establish liveness instead of retiring a healthy host on stale wall-clock time. Periodic state publication sends both the canonical semantic frame and its direct compatibility snapshot control envelope: the frame advances semantic authority, while the control snapshot independently renews transport availability. Only valid control envelopes and successful correlated full-snapshot responses refresh this deadline—event, notification, panel, failed responses, authority frames without their companion control snapshot, and other non-control traffic cannot mask a wedged control channel. Each valid refresh advances a control generation, so a subsequently failing older silence probe cannot publish stale unavailability. A correlated gap-repair response validates host identity and snapshot epoch against its own envelope, then atomically adopts that epoch; this permits repair when the missing frame was the epoch transition itself. A renderer must gate controls and both native/unified submission context on `availability === "available"`, not infer readiness from status, stale booleans, or transcript lifecycle events. Main repeats this availability check immediately before dispatch so unavailable/transitioning runtimes cannot receive prompt ingress.

Host control records carry transport identity and sequence. Initial extension binding commits its ordered records and terminal snapshot in the `ready` envelope; session replacement uses the same atomic transition-batch model for the new epoch. Replacement begins only after a fresh idle/no-admission/no-custody/no-command check, and ordinary command ingress is rejected once transition starts. Transition-sensitive events, UI/panel records, and submission outcomes are buffered (blocking UI may be provisionally published to avoid deadlock), then committed with one terminal snapshot. This prevents partial startup or an old runtime record from overwriting new state.

## Submission, ESC, and UI acknowledgements

The general deployed semantic mutation path uses owner-bound `session.dispatchIntent`; the child records the stable intent before possible Pi dispatch and frames the terminal outcome. Direct bare Escape is the explicit latency-sensitive transport exception described below. Other legacy mutation entry points may remain only as fenced adapters for compatibility, never as renderer/main mutation consumers. `session.submit`, `session.escape`, and correlated UI acknowledgements are delivery or presentation feedback only and cannot update canonical semantic state. Read-only `session.query` returns typed `ok`, `superseded`, `transitioning`, or `unavailable` results bound to its expected owner; `session.authorityAttach` returns typed `ready`, `transitioning`, or `unavailable` results. `session.submit` is the compatibility text/image submission API. The renderer includes an intent id, expected host id/epoch, editor revision, original input classification, transformed content, images, requested queue mode, and surface. Before Pi or delayed custody, the child validates that classification against the exact authoritative raw-editor revision and disables Pi's command/template expansion for ordinary input. The host then reports an explicit disposition. During compaction or navigation it takes the request into FIFO custody. Compaction drains that custody after its successful barrier; navigation drains only after its successful branch presentation is installed and acknowledged. Cancelled navigation converts affected custody into a non-replayable restoration record rather than submitting it. Failed, stale, or uncertain admission remains outcome evidence rather than being optimistically represented as delivered text; a record for an already-cleared intent can never reinsert that source. Picker continuations are separate bounded `pickerAction` intents: they carry only a validated selection after the source command's clear and do not weaken exact editor binding for arbitrary `invokeCommand` traffic. A dispatched request is conservatively unknown until its correlated disposition arrives. If an uncancellable preflight remains unresolved, the host keeps it visibly pending and an admission watchdog retires the identity rather than allowing later idle work to overtake it.

Bare ESC uses `session.escape` with a request id and the renderer's captured host/epoch. This latency-sensitive path deliberately bypasses the serialized semantic-intent ingress scheduler: a prompt or steering admission may still be awaiting Pi preflight, but Escape must reach the host's direct cancellation selector without waiting behind it. It must not be routed as an `interrupt` intent through that admission queue. While the semantic plane is synchronizing, this path alone may use the most recent owner installed by a validated authority attach, provided the session transport remains ready and available; it never treats the stale diagnostic snapshot as current semantic state, and main revalidates that owner immediately before dispatch. Main returns `not_applicable` without dispatch for stale/unavailable runtimes, and returns `outcome_unknown` if transport is lost after possible dispatch; it never sends a delayed ESC into a successor. The host directly chooses the applicable operation (navigation, compaction, retry, streaming, bash, or editor) and returns its acknowledged disposition. Navigation, compaction, retry, streaming, and bash are cancellable. Every direct Escape also advances a child-owned admission generation: each `prompt()` whose successful public `preflightResult` callback had not fired is moved to its own correlated `outcome_unknown` restoration with the exact intent and attachments, so main can reconcile mixed persisted/not-persisted admissions independently. If delayed extension input/preflight later resumes, the generation check throws before an idle `_runAgentPrompt`. Pinned Pi's streaming path instead appends before this callback. For an ordinary raw prompt with no input handlers—or whose handlers' final public `ExtensionRunner.emitInput()` result is `continue`—the bridge's admission context can attribute the exact one-slot `queue_update` to its positional queue slot even if unrelated work appends later; the callback then uses public `clearQueue()` and excludes every attributed cancelled slot already owned by a per-admission restoration. The bridge observes that public result once at the live prompt boundary and never executes input handlers twice. A handled input may append no prompt at all, and transformed or concurrent additions may be ambiguous, so the host never assumes the cancelled prompt is newest: it preserves every unattributed cleared text slot, labels successfully cleared remainder `not_processed`, and excludes every cancelled intent's attachments and correlation ID from that generic record. Later app admissions remain fenced until cleanup settles, and only then does the callback throw. Pi's subsequent caught `preflightResult(false)` cannot replace the already-published conservative outcome. Any effect inside the extension hook itself remains intentionally unknown. For streaming, the host calls public `AgentSession.abort()` first so its controller is signalled synchronously; queue observation, clearing, and restoration bookkeeping happen only afterward and cannot suppress that signal. A cleanup exception reports that abort was requested but restoration is uncertain, installs a permanent fatal fence against custody drain, lifecycle replacement, and queued or new semantic dispatch, and asks main to retire the child. Interrupting streaming otherwise emits a correlated queue-restoration record (empty markers are silently acknowledged by the renderer) and clears non-empty runtime queues under host authority. Because Pi exposes transformed text without attachment identities, the host retains every potentially queued original attachment while that queue mode remains non-empty and presents ambiguous originals unpaired rather than guessing by queue position. Main emits one idempotent, compatibility-named `session.restoreDraft` settlement. Any record with `clearedIntentIds` is unconditionally dropped and fences predecessor editor recovery; the renderer applies the ID once, never injects or merges payload text/attachments, and acknowledges it without showing restoration UI. See [ADR 0004](../decisions/0004-silent-reconciliation-replaces-user-review.md).

Queued-item controls use the owner-bound `manageQueue` intent, never an untyped renderer-side queue edit. The renderer intentionally exposes deletion and safe intra-lane movement, not queued-text editing. The public Pi SDK exposes only queue reads, `clearQueue()`, `steer()`, and `followUp()`; it has no stable item IDs or per-item mutation API. A move, update-compatible protocol call, or clear therefore requires one serialized direct read proving that every queue slot is a Pi-Vis-owned, untransformed, attachment-free plain prompt with retained original payload and no unresolved admission claim. Removing one stable Pi-Vis-owned target is narrower: the removed payload itself is never replayed, so it may carry attachments, but every remaining slot must pass the same exact rebuild proof. The authoritative availability projection publishes `removableIntentIds` when only those target-specific deletions are safe. Transformed or extension-owned slots still have no stable public identity and remain non-deletable. The child clears and rebuilds both queues synchronously in the same JavaScript turn, suppressing transient `queue_update` presentation, then publishes one final authority frame. Any extension-owned, stale, ambiguous, or partially rebuilt remainder is rejected or `outcome_unknown` rather than guessed, replayed, or silently reordered. Clear additionally carries the renderer's exact two-lane intent-ID expectation so a stale Clear all cannot remove newer work.

The renderer attaches with a monotonically increasing generation. During cold/starting activation, `session.rendererAttach` records that generation before returning typed `host_cold`; this is renderer ownership only, not semantic attachment, and lets a pre-ready project-trust dialog receive an owner-fenced answer so the host can finish startup. A brand-new session can publish that prompt before its ordinary attach call; in that narrow case, an exact pending response whose operation id, dialog id, host UUID, and epoch all match may atomically claim a newer renderer generation. Stable semantic authority still attaches only after the host is ready and available, and arbitrary, stale, or post-ready responses cannot claim ownership. Reattachment cancels blocking host UI from the old generation and requires an acknowledgement. Dialog responses and panel-close requests also carry operation ids and are accepted only after host acknowledgement. Panel input has per-panel sequences acknowledged by the host; main advances its cumulative acknowledgement only after host acceptance, and a gap is reported so the renderer can repair rather than silently advance. If owner retirement or replacement rejects an already-dispatched panel request, main rechecks the captured owner after the await and returns bounded `runtime_unavailable` or `runtime_replaced` instead of leaking the child-channel error through Electron IPC; an error from a still-current owner remains diagnostic. The renderer seeds each sequencer from the panel baseline's cumulative acknowledgement, and a unified panel's delivery tail plus rejected-input mailbox are owned by the full panel identity rather than its React mount. Each open also owns an explicit input generation: panel/session close retires it before queued work settles, an exact-tuple reopen activates a distinct successor, and post-await acknowledgement, reset, and recovery-repaint paths must still hold their captured generation. A session switch therefore cannot reorder or orphan an in-flight key: unacknowledged input remains fenced and is released only after the replacement terminal has drained an acknowledged reconstruction. A custom panel or viewport-mode unified overlay routes a globally consumed bare Escape into its current xterm only when its full `(hostInstanceId, sessionEpoch, panelId)` identity is still mounted and its panel plane is `following`, input-enabled, and revisioned. That xterm input enters the ordinary panel-input sequencer exactly once; during reconstruction or replacement it is consumed without allocating a sequence or falling through to `session.escape`. Editor changes and unsent attachment payloads use revisioned compare-and-apply patches, so renderer reload and explicit close do not lose component-local attachments. A unified-editor Enter carries its captured host editor revision and a main-assigned stable intent. Before any shared action runs, its renderer generation atomically claims the request with an unguessable claim ID and bounded deadline. Main replays only unclaimed requests while the same host identity/epoch still owns them. A claimed request that loses its renderer, host, or deadline becomes non-replayable `outcome_unknown`; main tombstones its stable intent, releases the host editor without restoring ambiguous text, and rejects late renderer acknowledgement. Renderer continuations also check the deadline/runtime after every await so late toasts, pickers, transcript writes, file hydration, and acknowledgements cannot land. Restoration acknowledgement is transport confirmation after `session.restoreDraft` application; it cannot release a late unresolved submission. Host failure retains only non-replayable Unified outcome/correlation evidence, not a draft payload, and never executes or reinserts the submitted source against the replacement host.

Renderer detachment is a retryable synchronization obligation, not a best-effort notification. The child fences every public TUI input parser (including partial bracketed-paste and terminal-negotiation fragments) before resetting its panel sequences and acknowledging; main keeps its prior sequence mirrors, refuses authority attachment and panel traffic, and retries the same-generation detach until that acknowledgement proves a common boundary. A panel-input RPC timeout is likewise delivery-uncertain: the renderer retains the attempted sequence with its bytes and requests reconstruction. The serialized repaint response and every exact-current panel keyframe carry the host input watermark; main advances its gate before forwarding a following keyframe, while the renderer drops an uncertain chunk only when that watermark proves it was consumed and otherwise replays it at the host's next sequence. Late RPC responses therefore cannot produce duplicate input or a permanent gap/repaint loop.

## Lifecycle and capacity

Activation starts only an SDK host. Startup failure leaves the session failed and unavailable; it does not change execution mode. Unexpected host failure marks retained in-custody/consumed intents `outcome_unknown`, clears host panels, and may make up to three short, backoff-delayed SDK-host restart attempts within a 30-second crash window. A fourth rapid failure stops the crash loop. An automatic restart is chained after retirement of the failed process; a successor cannot overlap a predecessor that is still exiting. Switching to a session is what normally reactivates a dead one, so a host that remains failed while its session stays active has an explicit renderer recovery: window focus / visibility retries one fresh activation visit for the active failed/exited session (`reactivateSession`), guarded against duplicate in-flight visits. Reload, planned worktree respawn, and narrow activation-visit release first request a serialized child lifecycle permit. The permit returns only `{ allowed, reason }`; it samples fresh SDK getters plus child custody, intents, editor, queues, and extension UI atomically. Main may combine that opaque verdict with transport identity and lifecycle fences, but never inspect snapshot liveness to make the decision. Reload repeats that admission immediately before creating its child transition. Lost acknowledgement is `outcome_unknown` and is never replayed.

There is no fixed registry-wide active-process limit. The registry does not use a generalized idle/LRU policy because an apparently idle established host may still own extension background work. It performs one narrow startup cancellation instead: when a renderer visit itself caused a cold session to activate and requests release within two seconds, without any editor, submission, command, panel, dialog, ESC, restoration, or admitted worktree action, `session.releaseActivationVisit` takes a fresh direct snapshot and reaps only that visit's host through its graceful disposal path. The release is refused for stale/pre-existing/older hosts, active/custodied/queued/editor/restoration/UI work, extension-published status/widget/working state, transitions, any open panel, or any interaction; returning during the check cancels it. Both normal and release-before-activation paths keep only a bounded two-second tombstone, so delayed discovery cannot turn the cancellation token into an unbounded lifecycle policy.

Planned retirement is IPC-first and awaitable. Main disconnects the child so its `disconnect` handler closes the outbound queue, disposes shell resources, and awaits public `runtime.dispose()`; this gives Pi 1.0.0's MCP stdio close sequence time to close stdin, wait 500 ms, send TERM, and wait two seconds before its own hard kill. The child has a four-second fallback. Main waits 4.5 seconds before SIGTERM and another three seconds before SIGKILL. User extensions can install signal handlers, so signal-first shutdown would bypass normal runtime disposal and can survive until a misleading SIGKILL. Diagnostics record the request and each escalation. A requested exit with code zero and no signal is recorded as clean lifecycle settlement rather than an error; code zero without a preceding `stop()` remains an unexpected authority loss. `SessionHost.stop()` is idempotent and resolves only on process exit; registry retirement is shared and awaited before asynchronous advisory-lock unlock, replacement activation, worktree replacement, activation-visit release, or automatic restart. Closing a tab first attempts bounded ESC/private force-close where applicable, then follows this retirement contract before removing the record. Persisted session files and worktrees remain on disk.

Application quit uses the same path rather than abandoning it. The first Electron `before-quit` event is prevented, marks the app as quitting, stops background schedulers, and starts one idempotent `stopAllSessions()` drain. Re-entrant quit requests share that promise. Only after search shutdown, every registry record, host exit, and advisory-lock unlock settles does main call `app.quit()` again and allow its resulting event through. Per-record lock settlement includes an acquisition that completes after shutdown starts and its required compensating unlock, so a late filesystem callback cannot recreate a lock behind the drain. An 8.5-second outer deadline is deliberately just beyond the host's complete 4.5-second graceful plus three-second signal escalation; it prevents a broken child-process implementation from trapping Electron forever without racing the ordinary host cleanup budget. Windows OS shutdown/logout may omit Electron's `before-quit` event and is the platform exception.

## Typed channels

Important invokes include `session.dispatchIntent`, `session.authorityAttach`, `session.acknowledgeNavigationPresentation`, `session.query`, `session.submit`, `session.escape`, `session.runtimeResync`, `session.rendererAttach`, `session.releaseActivationVisit`, `session.claimUnifiedSubmit`, `session.editorPatch`, `session.loadHistory`, `session.shellInput`, `session.shellResize`, `session.shellReconstructionAck`, `session.shellSignal`, and `session.close`. History conversion yields cooperatively while `session.loadHistory` retains single-response delivery. `session.rendererAttach` reports typed `unavailable` when a cold/unresponsive host, unconditional close, or runtime replacement wins the race; `session.authorityAttach` likewise reports host liveness loss as typed unavailability. A transport fence, closed child IPC channel, child exit, or request deadline rejects a pending attach as typed liveness unavailability so it can retry after correlated repair instead of silently discarding the response or surfacing an Electron handler exception. Stale renderer lifecycle work is not an exceptional IPC handler failure. Worktree replacement uses `session.createWorktree` / `session.attachWorktree`; main performs child-authority admission before replacement. Established-session creation and fresh-session creation with local-change copying send `fromCurrentCheckout` instead of a renderer-selected base, so main resolves and revalidates the exact HEAD of the session's current checkout. The explicit `copyUncommitted` flag chooses whether main also snapshots and transfers staged, unstaged, intent-to-add, and non-ignored untracked state before replacement. A clean fresh-session creation may instead supply an arbitrary selected `base`. Diff history uses `git.commits` plus optional immutable `range` fields on `git.changes` and `git.fileDiff`; these contracts live in `src/shared/git.ts` and `src/shared/ipc-contract.ts`. Main→renderer authority publications carry semantic frames and independent transcript, extension-UI, and panel planes. `session.runtimeState`, `session.submissionDisposition`, and `session.uiAcknowledged` remain compatibility diagnostics/presentation events; they cannot supersede an authority projection. The child-owned `queue_restoration` authority record is internal, not a renderer-visible IPC event. Main resolves it into the separate one-way, compatibility-named `session.restoreDraft` settlement event, followed by `session.acknowledgeRestoration`; the event never authorizes editor reinsertion. A delivered user `message_start` may carry its host-correlated GUI queue intent so ownership never depends on extension-transformed text. See `src/shared/ipc-contract.ts` and `src/shared/pi-protocol/runtime-state.ts` for the schemas.

Extension update awareness uses cached `extensionUpdates.status` invoke/event traffic plus `extensionUpdates.check` and `extensionUpdates.run`. The status cache and check single-flight live in main, so the delayed launch check and a concurrently opened Settings view share one worker. These channels describe user extension packages only; the pinned Pi runtime is not part of their contract.

Extension custom and unified pi-tui panels are host-rendered ANSI surfaces bridged through `session.panelEvent`, `session.panelInput`, and `session.panelResize`. One pi-tui paint may call its terminal several times synchronously (frame, hardware-cursor position, cursor visibility); the host batches that turn into one ordered panel publication so the renderer cannot observe or size an incomplete paint. The host is color-agnostic: it emits stable indexed ANSI roles and the renderer resolves them against the active scheme.
