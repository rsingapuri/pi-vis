# Conversation tree

`/tree` opens the native conversation-DAG overlay and changes the active leaf in place; `/fork` creates a separate session. **Opening the overlay is an unconditional renderer-local invariant:** command classification happens before runtime/editor admission, and the Composer keeps accepting `/tree` while semantic authority is synchronizing or unavailable (including compaction, abort, startup, and host failure). The overlay opens immediately with a retryable unavailable state and refreshes when semantic authority follows again. If no owner can durably consume the command source, `/tree` remains visibly staged in the Composer; an explicit retry under following authority atomically consumes it before it disappears. Runtime-backed attachments and every non-local submission remain fenced. The SDK host uses pi's public `sessionManager.getTree`, `getLeafId`, `getBranch`, `appendLabelChange`, and `session.navigateTree` surfaces. Tree support is an SDK-host capability; when the installed pi lacks a required public method, the overlay reports it as unsupported without changing runtime mode.

## Wire format

`getTree()` is recursive and can exceed Electron contextBridge's nesting limit. The host therefore sends flat `{ entry, parentId, label?, labelTimestamp? }` nodes, so only shallow data crosses preload. The renderer reconstructs and traverses the nested presentation with explicit iterative stacks (`tree-flatten.ts`); session-controlled conversation depth must never become JavaScript call-stack depth.

After navigation, the returned in-memory root→leaf branch is converted by `entriesToTranscript`; Pi-Vis does not reread the session file because recently appended entries may not yet be persisted. Tree navigation is refused whenever the authoritative runtime snapshot is unavailable or its complete SDK `isIdle` fact is false, covering streaming, compaction, retry, bash, and other barriers without preventing the viewer itself from opening. The SDK host repeats the public `isIdle` check inside serialized navigate-intent execution immediately before `navigateTree`, closing the renderer-observation race with work admitted from another surface. Pi's public `isCompacting` getter also becomes true for branch summarization during `navigateTree`; while `runNavigation` owns that operation, authority masks the generic getter from the context-compaction reconciler. The renderer likewise recognizes context compaction only from the child-owned `activity.compaction` projection, never the raw SDK diagnostic bit. Navigation therefore cannot fabricate a compaction barrier or working indicator that lacks a matching `compaction_end`, and Escape continues to target navigation. Tree reads carry their captured cursor as observation context, but a same-owner semantic cursor advance does not stale their response; only loss of following authority or an owner/epoch replacement does.

A successful navigation captures its exact post-navigation branch inside the child before `runNavigation` can release custody drain. The terminal semantic outcome and journal retain only bounded target/leaf/status metadata; the live terminal record carries the branch as a fast path, while the child also owns a `pendingNavigationPresentation` escrow until the renderer acknowledges that exact owner and intent. Attach baselines repeat every ready, unacknowledged escrow, so a detached renderer or dropped/gapped publication cannot lose the selected branch. The escrow fences later semantic mutation, lifecycle replacement, and custody drain; a prompt admitted through the submission adapter waits in navigation custody rather than advancing Pi before presentation is installed. The session store—not the tree overlay—serializes branch conversion, validates following owner plus matching terminal target/leaf and newest presentation, atomically replaces the visible transcript, and only then sends `session.acknowledgeNavigationPresentation`. That install advances renderer history ownership, cancels any older persisted hydration, and marks the complete in-memory branch clean; a delayed JSONL read therefore cannot restore the prior leaf after acknowledgement. A renderer-local completed-presentation tombstone also turns a stale pre-ack attach baseline into acknowledgement-only work, so it cannot reconvert over transcript events already released in the attach replay. Conversion and acknowledgement failures retain custody and receive bounded backoff retries, while session removal cancels their bookkeeping. Closing the overlay stops only viewer-local waiting; it never cancels reconciliation. Viewer and navigation generations prevent an older continuation from closing a later same-session overlay. A slower earlier conversion and every predecessor-owner result fail the compare-before-commit guard, so neither can overwrite a newer branch.

The viewer mirrors the diff overlay's modal and Escape ownership conventions. Filtering is per-node, hidden ancestors reattach visible descendants, indentation follows actual visible branch points, and tool-result messages are identified from pi's assistant content. When filtering or folding hides the selected row, selection walks to its nearest visible ancestor and otherwise falls back to the final visible row; up/down navigation wraps at both boundaries, matching Pi's native selector. The selected row can be copied with its hover/focus `IconCopy` control or Cmd/Ctrl+C. Copy uses the existing `clipboard.writeText` IPC and extracts the full text from Pi's copyable message, custom-message, compaction, and branch-summary entries rather than their truncated one-line row summaries; bookkeeping-only rows stay disabled, and success is a transient check icon rather than a toast. The shortcut never takes ownership from an input, contenteditable, or native browser text selection, and it does not navigate or close the viewer.
